# ADR 0001：Go 模块化控制面

- 状态：接受，待业务实现
- 日期：2026-09-15

## 背景

企业团队需要在不同本地 AI 客户端之间协作，首版不能依赖统一模型厂商，也不宜先引入大量分布式服务。

## 决策

后端 Go、前端 TypeScript/React。领域模块共享代码库，API、Worker、MCP Gateway 可作为独立进程部署；PostgreSQL 为权威状态存储。MVP 优先私有部署和本地客户端接入，受控操作使用 Gateway 凭证。

## 替代方案

微服务优先增加部署与跨服务一致性成本；统一托管所有客户端会减少可接入的本地产品类型；将控制面嵌入某厂商 SDK 会破坏协议独立性，因此本阶段不采用。

## 后果与重新评估

单库模块边界需要代码评审维护；本地独立凭证绕行无法完全约束。当负载或安全隔离要求明确时拆服务，强制执行治理需求出现时增加集中 Runner，而不改 Task/Context 公共模型。
