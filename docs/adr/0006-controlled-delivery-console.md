# ADR 0006：受控交付与 Web 控制台

- 状态：已采纳
- 范围：M3 受控交付、M4 Web 产品闭环
- 前置：[ADR 0005](0005-m2-execution.md)

## 决策

继续使用 Go 模块化单体与独立 Worker，React/TypeScript 控制台由 API 同源提供。控制台直接使用公共 REST 契约，权限与状态校验集中在后端。

新增人工成果审核、Task Owner 最终验收、Git Provider 核验、工具策略、不可变调用意图及独立人工审批。审核记录只追加；已接受成果的来源、版本和摘要不可修改。拒绝任务后必须由人类重新授权执行。

首次满足的成果依赖记录 Artifact ID。下游领取时将该成果引用和关联的已发布 API Context 加入不可变快照；与显式任务输入冲突时拒绝领取，要求人类修正输入，避免悄悄替换版本。

## 工具与外部副作用

部署管理员通过受信配置登记下游端点、资源、参数 Schema、风险和独立凭证。项目管理员只能在已配置的项目工具中创建策略；Agent 不能注册 URL、改变风险或提交自己的身份声明。

工具配置内容参与版本指纹，修改端点、工具名、资源或 Schema 会使旧审批失效。审批还绑定 Session、Run、具体参数摘要、资源版本、成果、策略版本和有效期；请求人不能审批自己的委托操作。

Worker 先提交 RUNNING 意图，再在项目授权锁内重新校验，并执行有时限的外部调用。调用失败或进程中断后保留 UNKNOWN，通过下游操作查询核对，不自动重放副作用。GitHub 合并使用服务端的 Commit SHA 前置条件；通用 MCP 下游需要执行操作 ID 和资源版本约定。

通用 MCP 不能凭空保证外部系统幂等。没有操作查询能力的工具必须保留 UNKNOWN，由操作者核对；有更强强制隔离要求时再引入 Runner 和受控出口。

## Web 身份与存储

生产控制台通过 OIDC Authorization Code + PKCE 登录，API 按配置的 issuer/audience 验证 ID token 并映射已有成员。开发环境使用原有个人凭证，保存在页面内存，刷新后重新登录。前端不内置演示 token，不提供冒充任意用户的登录接口。

正文和结果仍使用 PostgreSQL 中的有界存储：Context/Artifact 文本最多 256 KiB、工具参数 64 KiB、结构化结果 256 KiB。外部 Git diff 最多 4 MiB，通过服务端读取和摘要核验。达到大文件需求后再接入 S3，保留现有 URI/摘要与权限模型。

## 代价与验收

项目级锁简化权限撤销与操作提交的顺序；有时限的外部调用期间，同项目写入可能等待。试点后依据实际并发与延迟再拆分锁和专用执行进程。

合并入口继续采用人工 PR 审核。M3/M4 验证包括数据库集成测试、真实 MCP 传输、Git Provider 模拟服务测试、浏览器操作和本机 Compose 部署。首次交付时按 Owner 指示暂缓真实客户端联合验收。2026-09-16 已完成单人双客户端样例并由 Owner 接受，保留心跳间隔等限制，见 [验收记录](../acceptance-2026-09-16.md)；多成员与生产验收仍需单独开展。
