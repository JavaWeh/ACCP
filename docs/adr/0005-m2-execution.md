# ADR 0005：M2 受限执行身份与持久协作

- 状态：已实现（M2）
- 日期：2026-09-15

## 背景

M1 已提供人类 Task/Context 控制面。M2 需要让独立的本地客户端在明确授权、固定输入和可恢复执行记录下协作。Web 控制台继续保持在后续产品阶段。

## 决策

1. Session 与人类身份分离，绑定项目、Agent、人类委托人、权限范围及有效期。每次请求检查当前成员状态、委托范围和运行租约；Agent 无法调用人类管理、发布和审批接口。
2. 使用带专用服务端密钥的受限 Session 凭证。数据库和幂等记录不保存明文凭证；幂等重放在当前权限校验后重建凭证。密钥变化使旧凭证失效。
3. 延续项目事务锁，原子领取 Task、建立不可变 ContextSnapshot、分配单调 fencing token 和 90 秒租约。数据库限制每个 Task 一个活跃 Run；重试创建新 Run。
4. PostgreSQL 保存权威状态；Outbox 经 JetStream 持久投递，Inbox 去重后建立事件读取记录。API 通过轮询或 SSE 暴露同一授权读模型，不将消息总线开放给客户端。
5. Worker 处理租约失联、授权失效、可解除的依赖、失败投递及人工重放。重放不直接执行外部生产操作。
6. 完成候选须引用本次 Run 的成果。M2 提供最小成果登记和不可变文本上传，保存责任链；外部 Git 引用保持未核验。Git Provider 核验、成果接受、Task 最终 DONE、审批及 Gateway 属于 M3。
7. 依赖支持目标协议中的 TASK_DONE 与 ARTIFACT_ACCEPTED，满足条件以数据库的人类验收事实为准；M2 不为释放依赖伪造验收。缺少 M3 验收事实时依赖保持阻塞。
8. 提供厂商无关 Go 客户端 SDK、独立 Local Bridge 和标准 MCP stdio 工具。Bridge 只调用 ACCP API，不启动模型推理、不解析聊天文本判断完成、不持有人的长期凭证。

## 协议修正

新增 v0.2 执行契约，复用未变更的 v0.1 核心领域模型。领取请求明确携带本地不可变 `base_revision`；M2 记录客户端声明，外部真实性核验留待 Git Provider。握手仅声明实际可用能力，未部署 Gateway 时不返回 `mcp_uri`。只支持 v0.1 的 Adapter 会得到不兼容错误，不能假装协商成功。

## 代价与重新评估

项目串行写入保持权限与幂等边界清晰，但限制高吞吐项目。Session 凭证密钥需持久保管，多副本使用同一配置。Context 和最小成果文本暂存 PostgreSQL；大文件、细粒度资源 ACL、隔离 Runner 和外部操作强制治理继续在后续阶段实现。

本地客户端已有独立凭证可以绕过平台，本期仅保证经过 ACCP 的协作协议行为。真实客户端兼容性以实测版本和记录为准，不以测试替身冒充真实 AI 客户端。
