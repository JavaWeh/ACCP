# ADR 0004：M1 控制面实现边界

- 状态：接受
- 日期：2026-09-15

## 背景

设计与协议基线已建立。M1 需要交付可以独立运行和验证的人类控制面，为异构 Agent 执行提供后续基础。完整 MVP 模型仍有效，首个运行版本需要清楚区分已实现能力。

## 决策

1. 引入 Go 模块化 HTTP 服务和 PostgreSQL 17，使用 `net/http`、pgx、OIDC/JWKS 验证器与 draft 2020-12 JSON Schema。公共契约直接嵌入二进制作为请求验证依据。
2. M1 只接受预置人类身份，项目成员和角色可查询，ADMIN 可修改角色/停用状态。企业和项目由操作者首次 bootstrap 建立；没有自助注册或角色自动授予。
3. 实现 Task 创建/查询/SUBMIT/CANCEL 与 Context 正文/候选版本/人工发布。执行快照及人类成果验收与 TaskRun/Artifact 一起后移，避免空实现破坏证据链。
4. 小型 UTF-8 Context 正文暂存 PostgreSQL，限制 256 KiB；后续用同一不可变 URI 与摘要模型接入 S3 存储。M1 拒绝外部 URI 获取，外部来源核验以后再实现。
5. M1 以项目行锁串行化写入，使角色撤销、幂等请求、版本校验及业务变更保持清晰事务边界。业务成功、审计和发布 Outbox 原子提交；不引入事件投递依赖。
6. PostgreSQL 外键负责跨组织/项目关联约束；内容、已发布版本和审计的修改由数据库触发器拒绝。运行账户应与迁移账户分离；不将数据库管理员视为被此机制约束的攻击者。
7. 开发凭证随机生成并仅存本地文件，服务显式选择开发认证才接受。生产默认 OIDC，使用专门的 API audience 与经操作者确认的人类 subject。

## 代价与后续

项目写入串行化限制吞吐量；M2 有并发执行需求时可细化锁粒度，但必须保留权限撤销和幂等事务不变量。当前存储与审计满足人类操作追踪，不提供 Agent 运行证据链、敏感事件投递或完整拒绝审计。

OpenAPI 保留整个目标协议，并用里程碑字段区分运行支持。M1 的新增内容/身份查询接口是预发布协议的增量扩展，不修改既有请求的核心语义。完整启动与验收方法见 [M1 控制面](../m1-control-plane.md)。
