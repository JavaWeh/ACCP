# v1.0.1

Maintenance and feature-reconciliation release. `v1.0.1` tags `main` so the shipped
identity matches the code: the `v1.0.0` annotated tag points at an earlier commit and
its notes describe features (US-5 gitprovider sync, keep-login, organization-ADMIN
management, M5 US-14/14b/15) as "open / not in release" that have since landed on
`main`. This release moves those into "included" and records their residual gaps
honestly. Prefer digest-pinned images from the GitHub Release; do not install from a
floating `latest` tag.

## Highlights

- **M5 / US-14** — project member add + project-level deactivate, with console flows.
- **M5 / US-14b** — account-level deactivate, organization-ADMIN only (new `is_org_admin`
  role storage). Project-ADMIN cannot deactivate accounts (403); organization-ADMIN is
  required.
- **M5 / US-15** — project create / archive / restore + repository register from the
  console.
- **Organization-ADMIN grant/revoke + account reactivate** — `POST
  /organization/members/{user}/changes` with a `HumanChange` oneOf `active` /
  `is_org_admin`; `LAST_ORG_ADMIN` → 409, `INACTIVE_ACCOUNT` → 422. Reactivating an
  account does **not** auto-restore prior project memberships or re-sign live sessions
  (documented behavior).
- **Keep OIDC session across same-tab refresh** — the Web console stores OIDC user and
  state in tab-scoped `window.sessionStorage` so a same-tab reload no longer forces a new
  login. `automaticSilentRenew` remains `false`; token **expiry** still requires
  re-authentication; closing the tab clears the session. (Not `localStorage`; not shared
  across tabs.)
- **US-5 (partial, honest)** — live gitprovider token sync with 401/403 split and a live
  acceptance path. This release does **not** close US-5: acceptance passed with an **oauth
  token** only (`gh auth token`), **not** the fine-grained read-only PAT, and the
  end-to-end sync through the control plane / database was not exercised here. See Known
  limits.
- **Stage C P2 closures** — docs de-staleness (P2-1), additional DB-free control-plane
  short tests (P2-2), Windows Playwright exit fix (P2-3), bundle-size assessment (P2-4).
- **WP-4 / US-16 / D04** — W0-scale restore drill closed
  (`docs/restore-drill-w0-2026-10-28.md`: 50/50 login sample, business RTO 53.107 s,
  prod Compose + empty JetStream, full doctor PASS, ops-check grants fixed). Real
  enterprise IdP/Q8 multi-user drill remains an **accepted skip** (see US-17 below).
- **OIDC CI assertion sweep** — browser acceptance assertions scoped to unique targets,
  exact repo-URL matching, and `select-trigger` / `getByLabel` locator fixes across the
  OIDC acceptance suite.

All four `Validate` workflows (go control-plane+execution, Web console browser,
isolated-oidc production foundation, documentation+contracts) ran green on the tagged

## Compatibility

Supported upgrade-from: `v1.0.0` (`docs/releases/v1.0.0.md`) and `v0.1.0-rc.1`
(`docs/releases/v0.1.0-rc.1.md`). Fresh install is also supported.

- **Upgrade from `v1.0.0`**: apply the one new migrate file `007_org_admin.sql` and re-run
  grants (see Migrations / Grants). No other schema change is required.
- **Upgrade from `v0.1.0-rc.1`**: apply `006_task_query.sql` (per the `v1.0.0` notes) and
  then `007_org_admin.sql`, then re-run grants.

Untagged or pre-RC builds should treat this as a new install after backup, or follow the
documented adopt path separately.

## Migrations

Apply the normal production Compose sequence (`migrate` then `grants`) before returning
traffic.

1. **`007_org_admin.sql`** (new on `main` relative to the `v1.0.0` tag): adds
   `human_users.is_org_admin boolean NOT NULL DEFAULT false` and backfills the single
   lowest-id active `ADMIN`-role member as the initial organization-ADMIN. This is
   required before the organization-ADMIN management and account-level deactivate flows
   (US-14b) work on an upgraded install.
2. **`006_task_query.sql`** is still required for the M4 Web task list/search (unchanged
   from `v1.0.0`). It runs `CREATE EXTENSION IF NOT EXISTS pg_trgm`; existing upgrades
   must ensure `pg_trgm` already exists (created once by a privileged role). Do **not**
   grant the migrator durable database-level `CREATE` solely for this step. Installs
   already at `v1.0.0` have this applied.
3. No additional migrate files beyond current `main` are required for this tag once
   `006_task_query.sql`, `007_org_admin.sql`, and grants have succeeded.
4. After restore, confirm `accp.tasks_search_trgm` (or equivalent) is present; production
   dumps include `--extension=pg_trgm` so restore recreates the extension with the schema
   dump.

## Grants / privileges

Production installs must apply `deploy/production/grants.sql` after migrate. This release
adds one targeted grant beyond `v1.0.0`:

- `accp_api` gains `UPDATE(id, active)` on `accp.human_users` so account-level deactivate
  (US-14b) can toggle `human_users.active`. `human_users.is_org_admin` stays
  operator/bootstrap-only — runtime roles are **not** granted `UPDATE` on it. The existing
  targeted `DELETE` on `accp.task_contexts` (for editable-task context re-select after
  D09) is unchanged.

`deploy/production/check-privileges.sql` now also asserts that `accp_api` **has**
`UPDATE` on `human_users.active` and **does not** have `UPDATE` on
`human_users.is_org_admin`.

Verify with:

```sh
accp-ops check --database-url-file /run/secrets/migrator_url
```

On failure, re-run grants:

```sh
docker compose -f deploy/production/compose.yaml run --rm grants
```

Skipping grants can silently break D07 context re-select and the US-14b account-deactivate
path on upgraded or adopted environments.

## Config / secrets / compose

1. No new secret file names and no new env vars for this release. The optional
   **`ACCP_DATABASE_MAX_CONNS`** (default `10`, valid 1–1000) on API/Worker introduced in
   `v1.0.0` is unchanged.
2. Keep the SPA client ID (`ACCP_OIDC_CLIENT_ID`, example `accp-web`) distinct from the API
   audience (`ACCP_OIDC_AUDIENCE`, example `accp-api`).
3. Production still pins `ACCP_IMAGE` (and the ops image for backups) to Release digests;
   dev Compose may expose metrics on `ACCP_METRICS_ADDR` / host `ACCP_METRICS_PORT`.

## Breaking / operator actions

1. **Apply `007_org_admin.sql` and re-run grants before returning traffic.** On an
   upgrade from `v1.0.0`, the organization-ADMIN management and US-14b account-deactivate
   flows require both the new column and the new `UPDATE(id, active)` grant on
   `human_users`. Confirm with `accp-ops check`.
2. Pin `ACCP_IMAGE` (and the ops image for backups) to the digests published on this
   Release; do not use mutable local tags as the install identity.
3. After migrate, always run grants and confirm with `accp-ops check` before returning
   traffic.
4. Do not use `down -v` during upgrade or maintenance; named volumes hold PostgreSQL,
   JetStream, and Caddy state.
5. **Organization-ADMIN is a distinct, scarce role.** Revoking the last organization-ADMIN
   returns `409 LAST_ORG_ADMIN`; acting on an inactive account returns `422
   INACTIVE_ACCOUNT`. Reactivating an account does not restore prior project memberships or
   re-sign existing sessions — re-grant memberships explicitly if needed.
6. **Web session on reload**: a same-tab refresh now keeps the OIDC session (tab-scoped
   `sessionStorage`). Closing the tab or token expiry still requires re-authentication;
   operators should not assume cross-tab or persistent sign-in.

## Known limits

1. **US-5**: live gitprovider token sync is included but **not closed**. Acceptance passed
   with an oauth token only, not a fine-grained read-only PAT, and the end-to-end sync
   through the control plane / database was not exercised in this release. Closing US-5 to
   spec is tracked as WP-3 (requires an FG-PAT + fixture repo).
2. **US-17 / Q8**: documentation only. The real enterprise IdP rotation/expiry drill
   remains an **accepted skip** by product decision (not executed; not claimed). WP-4 /
   US-16 / D04 W0 restore drill is **closed** and no longer listed here; see Highlights
   and `docs/restore-drill-w0-2026-10-28.md`.

(M5 US-14/14b/15 and keep-login, listed as limits in the `v1.0.0` notes, are now
**included** in this release and removed from this list. The former WP-4 / US-16 modest-
drill caveat is likewise removed after the 2026-10-28 W0 closeout.)
