# v0.1.0-rc.1

First release candidate for ACCP. Prefer digest-pinned images from the GitHub Release; do not install from a floating `latest` tag.

## Compatibility

Fresh install only. There is no supported upgrade-from version for this first RC. Operators with earlier untagged builds should treat this as a new install after backup, or follow a documented adopt path separately.

## Migrations

None beyond the normal production Compose startup sequence (`migrate` then `grants`). No additional SQL migrate files are required for this RC relative to current `main`.

## Grants / privileges

Production installs must apply `deploy/production/grants.sql` after migrate so `accp_api` receives the targeted `DELETE` privilege on `accp.task_contexts` (required for editable-task context re-select after D09).

Verify with:

```sh
accp-ops check --database-url-file /run/secrets/migrator_url
```

On failure, re-run grants:

```sh
docker compose -f deploy/production/compose.yaml run --rm grants
```

Skipping grants can silently break D07 context re-select on upgraded or adopted environments.

## Config / secrets / compose

None beyond the documented production generator and Compose env (`ACCP_IMAGE` must be set to a digest-pinned `ghcr.io/javaweh/accp@sha256:…` from this Release). No new secret file names for this RC.

## Breaking / operator actions

1. Pin `ACCP_IMAGE` (and ops image for backups) to the digests published on this Release; do not use mutable local tags as the install identity.
2. After migrate, always run grants and confirm with `accp-ops check` before returning traffic.
3. Do not use `down -v` during upgrade or maintenance; named volumes hold PostgreSQL, JetStream, and Caddy state.
