# D07–D09 任务生命周期与 Git 资料来源

实施基线：2026-09-29，`javaweh/product-d07-d09`。范围沿用单企业、单机私有部署及 256 KiB 文本上限，不增加对象存储。

## D07：受约束的任务变更

- Owner 或项目 ADMIN 可编辑 DRAFT、READY、BLOCKED 任务的标题、目标、仓库、验收条件和已发布资料版本，也可移交给另一位有效的人类项目成员。写入要求当前 ETag、幂等键和原因。
- 任务存在 RUNNING Run 时不得编辑或移交。操作成功后任务返回 DRAFT，撤销本次领取授权，由负责人重新 SUBMIT；若已有历史 Run，使用 RETRY。旧 Run 的 Owner、快照、成果和审核记录均不修改。
- Owner 或 ADMIN 可将 DONE 或 CANCELED 任务归档。存在待审批、运行中或结果未知的工具操作时阻止归档。归档只隐藏于默认任务列表及工作台，详情与历史仍可读取；归档筛选中可恢复。
- 负责人移交将旧、新负责人及原因写入不可变审计。任务版本变化会使旧 If-Match 写入失败。

## D09：受控 Git 文本来源

- Git 来源 URL 必须位于当前项目已登记的 GitHub 仓库及其默认分支下。同步时指定完整的 40 位 Commit SHA；后端用该 SHA 读取指定路径，拒绝可变分支引用、跨仓库路径、非文本和超过 256 KiB 的内容。
- 同步将正文、SHA-256 摘要与 Commit SHA 保存为不可变候选版本。人工审核人对照当前发布内容、候选内容和最多 20 条仍引用旧版本的进行中任务后，填写理由发布；任务总数单独报告。
- 发布不会把旧任务或 Run 快照切换到新版本。负责人如需采用新资料，须在可编辑状态显式更新任务输入并再次提交。直接上传正文仅适用于 ACCP 来源，不能绕过 Git 来源同步。
- GitHub 使用现有服务端 `ACCP_GITHUB_TOKEN`；只请求 GitHub API，不跟随重定向。当前没有二进制文件或对象存储支持。
