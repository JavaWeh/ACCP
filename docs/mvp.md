## MVP 范围

私有部署、单企业、多项目、多成员。首版含任务看板、Owner、依赖、单活跃 Run、租约、手动重试、人类验收；Context 候选/发布版本和快照；Artifact 与审计时间线；Local Bridge 与通用 CLI/MCP 接入；网关工具目录、权限和审批。

首个 Git Provider 实现 GitHub 的 Commit/PR 核验与受保护分支合并；领域接口保持 Repository/Commit/PullRequest 通用概念。数据库、CI、文档通过登记的 MCP 服务接入，不为每类系统另造完整连接器。

完整 MVP 验收需选取两个不同厂商的真实客户端完成同一流程；该项按 Owner 要求暂缓，M4 产品功能完成不代表此项已经通过。当前不宣称任何客户端已兼容，实施时记录版本与经过验证的能力。

| 接入模式 | 基线声明 | 实际兼容性 |
| --- | --- | --- |
| Local Bridge + MCP 客户端 | 人类启动，工具领取与报告，协作取消 | 待验证 |
| CLI Adapter | 进程参数化接入，协议 I/O 转换，显式能力 | 待验证 |
| 自动启动、强制终止进程 | 可选能力，不作为所有客户端前提 | 待逐客户端验证 |
| 集中隔离 Runner | 后续阶段 | MVP 不提供 |

## 实施阶段

1. **M1 领域与身份（已实现）**：数据库边界、OIDC、成员角色、Task 创建/提交/取消、Context 正文/版本/人工发布。
2. **M2 异构执行（已实现）**：依赖 DAG、TaskRun、执行快照、Adapter SDK/Bridge、claim、租约、心跳、Outbox/Inbox、事件订阅与重放。
3. **M3 受控交付（已实现）**：Artifact、Git Provider、Gateway、审批 Worker、审计责任链。
4. **M4 产品闭环（功能已实现）**：Web 任务/Context/成果/审批界面、浏览器验收与故障处理；两种客户端联合验收暂缓。

每阶段遵循公共契约，发现设计错误先记录 ADR 并同步契约，不绕过领域约束补丁式接入厂商 SDK。

## 运行时验收矩阵

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| M01 | 三个人类成员、两种真实客户端完成订单 API 流程 | 任务、依赖、成果与最终验收完整闭环 |
| M02 | Agent 作为 Owner 或审批主体 | 服务端拒绝，保留拒绝审计 |
| M03 | Agent 报告成功或进度 100 | 只能进入待审，不能自动 DONE |
| M04 | 重复事件、重复 claim、报告重试 | 无重复活跃 Run、审批或副作用 |
| M05 | 跨企业/项目读取或关联 | 拒绝且不泄露资源正文 |
| M06 | 过期/撤销 Session、旧 fencing token | 不能续租、提交或发起受控副作用 |
| M07 | 执行中 Context 更新 | 原快照不变，Owner 得到更新通知 |
| M08 | 审批后参数、Commit、策略变化 | 旧审批失效，不执行新内容 |
| M09 | 消息服务重启、Worker 崩溃 | Outbox 继续投递，Inbox 去重，意图可核对 |
| M10 | 外部合并超时、结果未知 | 先查询核对，不自动重复副作用 |
| M11 | 任一最终成果回溯 | 可定位人类、客户端、Session、快照、操作及审核人 |
| M12 | 无 SSE 或不支持自动启动 | 通过轮询与人类启动仍可完成流程 |
| M13 | 私有内容或 token 出现在工具输出 | 不进入公共事件或普通审计日志 |
| M14 | DAG 循环、并发添加依赖 | 至少一个请求被拒绝，不形成循环 |
| M15 | 数据库与对象存储恢复演练 | 元数据、快照摘要、审计关联保持一致 |

上表是完整 MVP 验收要求。M1 已通过其中的人类 Owner、项目隔离与 Context 内容不可变等基础子场景；M2 增加 Agent 授权、快照、并发领取、重试、撤销和事件重放子场景。M3/M4 增加独立审批、网关凭证隔离、人工验收、不可变证据、未知结果及浏览器操作测试。真实客户端联合验收、真实 IdP、生产性能和完整恢复演练仍待执行，不能据阶段测试标记整个 MVP 验收完成。

## 非 MVP 范围

多租户 SaaS、跨企业协作、计费、可视化复杂流程设计器、全局向量记忆、集中 Runner、Kubernetes 编排及多区域容灾留待后续。容量与 SLO 在试点团队规模确定后通过压测制定，不以未测数字承诺性能。
