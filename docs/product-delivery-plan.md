## 结论与交付目标

当前处于“核心业务闭环已实现、具备受控试用基础”的阶段。任务、执行快照、成果、审批和审计已有较完整实现与测试；距离可交付产品的主要差距是企业持续管理、生产身份接入、日常协作体验、运行保障和版本交付体系。不能用 M1–M4 功能完成来推导生产可交付，也不能把剩余工作当作少量界面润色。

本计划建议将第一版成品定义为：**单企业私有部署、多项目、人类负责的研发协作控制面，企业管理员能够独立安装、接入成员和仓库、持续运营、升级和恢复。** 用户能够完成任务创建、受控执行、审核、返工和责任追溯，无须开发者改数据库协助日常操作。

本轮暂不计入多端联合验收：不同厂商客户端联合执行、跨客户端兼容矩阵和多人多客户端联合样例均单列延期。仍保留单端稳定性、多人权限回归、真实 IdP、Git/MCP 下游及恢复验证。这些是控制面交付要求，不依赖多端联合验收。

继续保留模块化单体、PostgreSQL、Worker、Gateway 和 Bridge。多租户 SaaS、计费、集中 Runner、复杂流程设计器、Kubernetes、多区域高可用均不因“成品化”自动进入范围。

## 正式交付门槛

以下是建议门槛，W0 冻结具体规模与指标后执行；不是本次已经测得的能力。

1. **独立安装与初始化**：由非原开发者按文档部署，接入真实 IdP，建立项目、成员、仓库与第一个受限 Session；日常配置不依赖直接写 SQL。
2. **完整人类闭环**：用一个受支持执行入口完成创建、运行、成果、独立审批、Owner 验收、退回重试；覆盖成员停用、Owner 移交、输入版本变化与不可变历史。
3. **权限与副作用不变量**：跨项目、撤销、旧 fence、审批参数漂移、重复提交必须拒绝或安全去重；UNKNOWN 必须先核对，不能重复产生副作用。
4. **真实外部系统**：真实 IdP、真实 Git 测试仓库及至少一个受控 MCP 下游通过正常与失败路径。此项无须多端联合执行。
5. **容量与稳定性**：在约定规模下测 API p95/p99、事件延迟、心跳成功率、锁等待、内存和数据库增长；建议至少连续 7 天混合负载观察，无未解释的失租、持续积压或增长异常。具体阈值由基线压测确定。
6. **恢复与升级**：在隔离环境恢复备份并比对关键数据与摘要；验证升级成功、迁移失败处理、配置回退和外部 UNKNOWN 核对；记录实际 RPO/RTO，不能只写目标数字。
7. **可用性与支持**：关键页面支持大数据分页、键盘操作和可理解的错误恢复；提供待办入口、可分享任务链接、版本信息与脱敏诊断材料。
8. **版本证据包**：提交 SHA、发布包/镜像摘要、测试结果、支持环境、限制、迁移/恢复报告和操作手册齐全；阻塞缺陷为零，其余缺陷有明确影响范围和负责人。
