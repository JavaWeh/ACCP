# ACCP Web 使用与支持指南

## 登录与访问

- 正式环境必须配置 `ACCP_ENV=production` 和 `ACCP_AUTH_MODE=oidc`，并提供 HTTPS Issuer、独立的 Web Client ID 与 API Audience。启动校验不接受生产环境的开发凭证模式。
- 使用企业账号登录。任务链接可直接打开；登录后会返回原任务。`/dev-login` 只在显式开发认证环境提供凭证表单，正式环境返回 404。
- 页面入口随项目角色变化。项目成员可创建任务和注册执行客户端；审核人可处理审批、查看审计；管理员可进入项目设置、工具治理和系统运行。后端仍独立校验权限。

## 日常任务闭环

1. 在“项目资料”创建并发布需求或接口说明的版本。管理员先登记代码仓库和项目成员。
2. 在“任务协作”创建草稿：写目标、选择负责人和仓库、逐行填写验收条件、选择已发布资料。缺少前置条件时页面会明确提示。
3. 负责人在独立的任务详情页检查草稿并提交执行。该页面 URL 可复制给同项目成员，刷新和登录后仍可直达。
4. 在“成果与验收”查看成果的核验状态、来源和内容摘要。接受交付前必须逐项确认验收条件并绑定至少一项已核验成果；不满足时选择退回修改并说明原因。
5. 工作台“我的待办”显示由你负责的待验收任务、执行异常及待审批数量。任务列表可按负责人、状态和关键字筛选，分批加载。

任务详情提供“编辑任务输入”和“移交负责人”。仅草稿、就绪或阻塞状态且没有活跃 Run 时允许操作；编辑或移交后任务回到草稿，负责人需重新提交。历史 Run、冻结快照和审核记录不变。已完成或已取消的任务可归档，归档前必须核对未结工具操作；任务列表中的“已归档”筛选可查看并恢复归档任务。

## Git 资料来源

管理员先登记 GitHub 仓库。创建项目资料时选择 GitHub 来源、已登记的仓库和该仓库默认分支内的文档路径。创建后填入完整的 40 位 Commit SHA 同步文件；服务端只从该提交读取不超过 256 KiB 的 UTF-8 文本，保存摘要并生成候选版本。候选版本不会自动发布。

审核人先点“查看差异与影响”，对照当前发布内容与候选内容，并查看仍引用旧版本的进行中任务，然后填写审核理由发布。发布不会改写已有任务的资料版本或 Run 快照；负责人可在任务详情中显式编辑输入并重新提交。当前 Git 来源仅支持已登记 GitHub 仓库中的文本文件；文件和大对象不在首版范围。

## 错误与重试

- 写入发生网络中断或服务端错误时，保留表单内容并重试同一操作。Web 会复用同一个幂等键，避免把未知结果重复创建。
- 如果收到版本冲突，刷新任务后重新核对当前状态再操作；不要盲目重复提交。
- 管理员在“管理中心 → 系统运行”查看事件失败、未知工具操作和恢复项。事件重放、工具核对都必须填写原因；外部工具结果未知时先查询真实结果，不能直接重放。
- “导出诊断”提供脱敏的当前页 JSON 快照与是否还有更多页的标志，供售后定位；不包含访问凭证或原始请求正文。完整恢复操作仍遵循 [运维手册](operations.md)。

## 交付前核验

运行 Web 构建与 UI 回归；在目标企业 IdP 环境执行 OIDC 登录、退出、会话过期和深链接回跳；用管理员、审核人、成员及只读用户分别验证入口和后端 403。服务端迁移 `006_task_query.sql` 需要在启用新 Web 版本前应用。新安装会由数据库管理员在初始化阶段创建 `pg_trgm` 扩展；现有安装升级时需先由有权限的账号在应用 schema 中创建该扩展，不应给迁移账号长期授予数据库级 `CREATE` 权限。容量验收应覆盖目标规模下任务搜索、分页和工作台统计的延迟。
