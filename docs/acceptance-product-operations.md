## 故障注入

使用内部 Prometheus，逐项停止并重新启动隔离服务。下列时间为脚本轮询实际观测值，包含采样和规则评估间隔。

| 服务 | 告警 | 触发时间 | 服务恢复后解除时间 |
| --- | --- | --- | --- |
| Worker | ACCPWorkerStalled | 85.276 秒 | 30.070 秒 |
| NATS | ACCPWorkerStalled | 90.255 秒 | 10.032 秒 |
| PostgreSQL | ACCPUnavailable | 25.065 秒 | 15.038 秒 |

故障期间的请求错误率和耗时告警使用五分钟窗口，随窗口恢复解除；不把故障注入期间的错误计为正常容量通过结果。

## 恢复指标与剩余验证

首次真实包快照为 `2026-09-17T02:45:48.121950Z`，模拟故障时间为 `02:47:00Z`，RPO **71.878 秒**，数据库恢复及自动隔离命令耗时 **1.442 秒**。这是小样本，不代表 10 万任务规模；命令时间不包含人工核对、权限重建和应用重新部署，因此不宣告完整业务 RTO 已达标。

首次独立卷样本中外部工具账本为空；非空未结账本、旧 Session 拒绝和不可变证据由额外数据库集成测试覆盖。

## 候选版本全规模恢复补验

2026-09-17 使用独立容量库的 50 人、20 项目、100000 个任务和任务 Context 关联、20 个执行快照、20 份正文成果、965 条审计、20 条工具账本完成真实加密备份。账本为 19 个成功、1 个已取消；非空 UNKNOWN 隔离仍由上述集成用例证明。备份快照为 `06:26:52.512264Z`，加密包 3296232 字节，包含迁移 001–009 和全部 43 张表的计数及摘要。

对该实际包使用其他私钥和截断副本验证，分别以认证失败、无效归档拒绝。在第一个全新卷的 DDL 阶段主动终止恢复进程，命令失败后 `accp` schema 计数为零；保留该卷，改用第二个全新卷恢复。全部表摘要一致，恢复命令耗时 **25.608 秒**，RPO **113.488 秒**。恢复默认进入维护和待核对状态；在核对前没有启动 Worker。

使用生产所有权和 grants 脚本重建四个受限角色，API/Worker 权限边界检查通过。备份前经过 HTTP 验证可用的 20 个 Session，在恢复后全部被拒绝；最小权限 API 账号仍可读取，业务写入返回 503。完成核对并退出维护后，同一 API 账号实际写入返回 200，旧 Session 仍全部被拒绝。事件、投递和 fencing 序列的下一个值均大于恢复数据中的最大值，未结工具数为零。

从空 JetStream 卷重建投递后，Feed 从 448 条增加到 471 条，仅补齐 23 条缺失事件，未入 Feed 数为零。生产 Worker 角色下连续执行工具调度，历史工具调用次数为零，19 个成功和 1 个取消账本保持不变，核验完成于 `06:49:23.0547971Z`。

模拟事故时间为 `06:28:46Z`，业务写入核验完成于 `06:41:17.3840493Z`，用时 751.384 秒。保守计入随后完成的空 JetStream 重建和工具不重放核验，完整业务 RTO 为 **1237.055 秒（20 分 37 秒）**，包括中断、换卷重试、权限重建、HTTP 与消息恢复。此为同机独立卷、开发身份数据和真实 HTTP 处理链的演练；生产 TLS/OIDC 接入由独立浏览器验收覆盖，不将结果表述为异地灾备或连续稳定性证明。

这些结果是运行保障包的证据，不是 D03–D10 整体候选版本通过，也不包含连续稳定性、多端联合验收或正式生产放行。操作说明见 [管理员运维手册](operations.md)。
