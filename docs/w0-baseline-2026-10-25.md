## 3. 规模目标（A1）

| 维度 | 冻结值 | 说明 |
|---|---|---|
| 组织 | 单组织（单企业） | 与生产部署手册一致 |
| 部署拓扑 | 单机 | Linux 上 Docker Compose；见 §5 |
| 人类用户（并发量级） | 约 **50** | 试点企业侧并发人类操作员量级 |
| 活跃 Agent 会话 | 约 **200** | 同时有效的 Agent/MCP 会话量级 |

以上为 RC 容量与体验验收的主靶。2026-09-17 交付计划中另有规划性数据量假设（如项目数、任务存量、并发 Run、主机规格、备份保留等），**未被 Q1 重新拍板**；若后续压测或恢复演练需要固定数据量，在 US-2 / US-16 方案中单独写明，并回链本文，而不在本文发明新承诺。

## 4. SLO 表（A1）

| 指标 | 冻结阈值 | 备注 |
|---|---|---|
| API 读延迟 | P95 **< 300 ms** | 控制面 REST 读路径 |
| API 写延迟 | P95 **< 800 ms** | 控制面 REST 写路径 |
| 事件可见延迟 | P95 **< 2 s** | 写入后事件对订阅方/控制台可见 |
| API 5xx 比例 | **< 0.1%** | 正常负载窗口内；故障注入窗口单独标注，不计入达标判定 |

**与历史短测阈值的关系：** 2026-09-17 [product-delivery-plan.md](product-delivery-plan.md) 引言中的短测口径（读 p95 ≤500 ms、写 p95 ≤1 s、非预期错误率 <0.5%、事件可见 p95 ≤5 s，以及短时 rps 波形）为**当时临时短测假设**，**不再作为 RC 冻结靶子**。RC 与后续 US-2 对照一律以本表 A1 为准。

## 5. 支持环境矩阵

与现有生产文档对齐；**不承诺**多区域、Kubernetes 或跨主机内网明文以外的拓扑。

| 维度 | 支持 | 不支持 / 非承诺 |
|---|---|---|
| 组织与部署 | 单企业、**单机** Linux **Docker Compose**（[production-deployment.md](production-deployment.md)） | 多租户 SaaS、多区域、跨区域容灾、Kubernetes 编排 |
| 运行时组件 | 生产 Compose 中的 **PostgreSQL**、**NATS JetStream**、**Caddy**（TLS 入口）；API / Worker / 迁移分权账号 | 把数据库或 NATS 暴露为跨主机明文服务且无另配 TLS（手册已排除该假设） |
| 身份 | 支持 **RS256 JWT** access token 的 **OIDC** IdP；SPA client ID 与 API audience 分离（见部署手册） | 本期不做「依赖目标企业 IdP」的专项身份演练（Q8）；开发用 bearer 不能代替生产 OIDC |
| 运维主机脚本 | 备份等运维入口以 Linux 为主；**Windows 主机**可按 [operations.md](operations.md) 用任务计划运行已文档化的 Node 备份命令 | 不以 Windows 宿主代替 Linux 单机 Compose 生产拓扑 |
| 客户端 | 浏览器控制台；Bridge/MCP 按现有平台文档 | 多端联合验收、多厂商客户端兼容矩阵（交付计划单列延期） |

硬件规格（如 vCPU / 内存）未在 A1 中重新冻结；压测报告须记录实际主机规格，便于对照。
