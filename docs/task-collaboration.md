# 任务协作与 Web 日常操作

## 人类任务变更

新增入口保持 `/api/v1`，所有 POST 要求 `Idempotency-Key`、当前 Task 的 `If-Match` 和非空原因。身份、企业和项目由服务端派生；Agent Session 不获得以下权限。当前 Owner 或该项目 ADMIN 可操作。

| 入口 | 条件与结果 |
| --- | --- |
| `POST /tasks/{id}/changes` | 仅 DRAFT；修改标题、目标及验收条件，增加任务版本 |
| `POST /tasks/{id}/owner-transfers` | 新 Owner 必须是当前项目有效人类成员；停止自动重试，READY 转为 BLOCKED |
| `POST /tasks/{id}/inputs` | 修改标题、目标、验收条件、仓库和明确 Context 版本；产生新的 input_revision。已有尝试回到 BLOCKED，由人类 RETRY；没有尝试回到 DRAFT。DONE / IN_REVIEW 先走已有验收或退回流程 |
| `POST /tasks/{id}/archive` | 只允许 DONE / CANCELED；设置独立归档标识，执行状态不变 |
| `POST /tasks/{id}/restore` | 移除归档标识，不自动提交或执行 |
| `GET /tasks/{id}/changes` | 分页读取不可变的变更前后内容、版本、操作者、原因和时间 |

全部变更都拒绝存在 RUNNING Run 或 AWAITING_APPROVAL、READY、RUNNING、UNKNOWN 工具操作的任务。先取消执行，并按现有治理核对未结操作。移交不改写历史 Run、快照、成果、审批与审计的责任主体。`task_changes` 仅允许运行账号追加，禁止更新和删除；业务证据长期保留。

归档任务不能通过旧命令或分配接口重新执行。恢复后仍需按原状态走明确输入更新和重新授权。项目授权锁、Run fencing、副作用绑定及唯一活跃 Run 约束继续生效。

## 分页与定位

未增加筛选参数的旧接口保留默认每页 50 条、ID 升序和旧游标。Web 每页 25 条，服务端上限 100。新筛选包括 `search`、`status`、`owner` 和任务专用 `archived=true|false|all`；排序支持 ID、标题、更新时间，Run 另支持 `-attempt`。新游标签名并绑定资源路径、筛选和排序，24 小时过期；改变条件后从首页读取。

任务、Context、成果、审批和工具列表按当前页面取数；执行记录、审核、版本、Session、工具操作和审计有独立分页。项目汇总由数据库计算，不能把一页数据当成总量。创建任务通过项目已发布版本检索选择依据；不会扫描每个 Context 的全部版本。

项目、页面、筛选、游标和任务定位保存在 URL。任务链接格式为 `/?project=项目标识&page=tasks&task=任务标识`，支持浏览器返回与直接打开；PKCE 登录保留同站点目标地址。每个项目复用一个事件订阅；收到完整事件页后确认游标，断线期间按需刷新当前页面并重连。权限撤销仍由每次服务端请求重新判断。

## 提交与冲突

同一未知提交在当前标签页保存原请求、If-Match 和幂等键，页面重新加载或重新认证后可重试原请求；不会保存 bearer token。浏览器禁用存储时退回内存保留。请求未明确前，修改请求内容会提示先核对原提交；确认后的重复点击不会再次提交。

收到 412 时重新读取资源并展示提交内容与当前内容，由用户重新编辑；不会自动覆盖。未知提交超过 23 小时停止自动重试，避免跨过服务端 24 小时幂等期限后重复执行，管理员须先核对审计及资源结果。
